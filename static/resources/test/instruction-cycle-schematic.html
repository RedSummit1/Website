STAGE 03 — THROUGHPUT

Your mainframe overlaps the stages

IBM Z processors don't finish one HLASM-assembled instruction before starting the next — the stages run in parallel on different instructions at once. Press P to advance the clock.

At any given clock tick, up to three different instructions in your program are mid-flight — one being fetched, one decoded, one executed. This is why clock speed alone doesn't tell you throughput on real Z hardware.
SUMMARY

Three stages, endlessly repeated

Fetch pulls the next machine instruction — the object code your HLASM source assembled into — from storage. Decode figures out the operation and operands. Execute carries it out on the Z hardware. Every AR, L, ST, or B you write becomes this loop, run at extraordinary speed.
